# HealTest AI — Backend

Express REST API + Playwright demo runner. The backend includes a local checkout page to demonstrate:
- **healable** — the original `#checkout-button` selector is gone; one matching replacement exists and the outcome is verified.
- **app-failure** — replacement action runs but the demo app returns an application-level error.
- **ambiguous** — two possible replacement buttons exist; the runner asks for human review instead of guessing.

## Requirements
- Node.js 20+
- npm

## Install and run
```bash
npm install
npx playwright install chromium
cp .env.example .env
npm run dev
```
Windows PowerShell alternative for environment file:
```powershell
Copy-Item .env.example .env
```
Server: `http://localhost:5000`
Health check: `http://localhost:5000/api/health`
Demo page: `http://localhost:5000/demo/checkout.html`

## API contract

### `GET /api/health`
Returns service status.

### `GET /api/dashboard`
Returns:
```json
{
  "stats": {
    "totalTests": 3,
    "healedTests": 1,
    "failedTests": 1,
    "needsReview": 1,
    "healingRate": 33
  },
  "recentRuns": []
}
```
Values above are illustrative; actual values are calculated from stored runs.

### `GET /api/runs`
Returns `{ "runs": [...] }`.

### `GET /api/runs/:id`
Returns one run object, including `logs`.

### `POST /api/runs`
Start a Playwright test asynchronously. Returns HTTP `202`; poll `GET /api/runs/:id` until status is not `running`.

Request:
```json
{ "scenario": "healable" }
```
Allowed scenarios: `healable`, `app-failure`, `ambiguous`.

Response:
```json
{ "id": "generated-run-id", "status": "running", "message": "Test run started." }
```

## Connect your React frontend
Set your frontend API base URL to `http://localhost:5000/api` (or create a Vite env variable such as `VITE_API_BASE_URL=http://localhost:5000/api`).

Example:
```js
const API_BASE = import.meta.env.VITE_API_BASE_URL || "http://localhost:5000/api";

export async function getDashboard() {
  const res = await fetch(`${API_BASE}/dashboard`);
  if (!res.ok) throw new Error("Could not load dashboard");
  return res.json();
}
export async function getRuns() {
  const res = await fetch(`${API_BASE}/runs`);
  if (!res.ok) throw new Error("Could not load runs");
  return res.json();
}
export async function getRun(id) {
  const res = await fetch(`${API_BASE}/runs/${id}`);
  if (!res.ok) throw new Error("Could not load test run");
  return res.json();
}
export async function startRun(scenario = "healable") {
  const res = await fetch(`${API_BASE}/runs`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ scenario })
  });
  if (!res.ok) throw new Error("Could not start test run");
  return res.json();
}
```

Dashboard stats are under `response.stats`; recent runs are under `response.recentRuns`. `GET /api/runs` returns `{ runs }`. The run details endpoint returns the run object directly.

## Important notes
- Run IDs, statuses, logs, selectors and verification results are generated by the backend.
- This is a hackathon-ready local demo, not yet a production test platform.
- JSON file storage is suitable for a single local server; use a database for concurrent/multi-instance production use.
- The demo healing rule uses accessible button text and a uniqueness check. It is intentionally conservative; it is not a general-purpose AI locator repair engine.
- To test your own website, add a trusted test definition and explicit expected outcomes. Do not blindly click the highest-scoring candidate or mark a test healed without verifying the actual outcome.
